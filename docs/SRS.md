# Software Requirements Specification (SRS)

## EQ Test 1.0

## 1. Purpose and scope

This document specifies the software behavior and implementation
constraints for EQ Test 1.0. The app is a local-first Flutter iOS
application. It has no first-party backend, user accounts, cloud sync or
server-side assessment processing.

## 2. System context

### 2.1 Runtime components

-   Flutter application.
-   Local relational database (SQLite via Drift or equivalent).
-   Bundled, versioned question and result-content assets.
-   StoreKit-backed non-consumable IAP through a maintained Flutter
    plugin.
-   Google Mobile Ads SDK or approved equivalent.
-   Flutter localization (`gen_l10n`).
-   Native iOS share sheet.

### 2.2 Data flow

Question assets → Question Repository → Assessment Session → Local
Answers → Scoring Engine → Result Generator → Local Result Repository →
UI.

IAP flow: Paywall → StoreKit purchase → transaction verification/state
update → local entitlement cache → feature gate. StoreKit remains the
source of truth; the local cache must be refreshed on app launch and
restore.

Advertising flow: consent/privacy state → ad eligibility check → ad SDK.
No question, answer, score, dimension result or assessment identifier
may be passed to ad SDKs.

## 3. Architecture requirements

Use feature-oriented structure with separation of: - Presentation:
screens, widgets, state controllers. - Domain: entities, use cases,
scoring rules and entitlement policies. - Data: repositories, local
database, bundled content, SDK adapters.

Recommended: - Riverpod for state management. - go_router for
navigation. - Drift/SQLite for structured local data. -
`in_app_purchase` or a maintained StoreKit 2-capable package. -
`google_mobile_ads` where permitted. - `flutter_localizations` and ARB
files. - `fl_chart` or equivalent for visualizations.

Do not introduce a backend, Firebase, remote configuration, remote
question delivery, account system, AI API or analytics platform in MVP.

## 4. Functional requirements

### 4.1 App and onboarding

-   SRS-F-001: App shall launch without network connectivity.
-   SRS-F-002: First launch shall show purpose, privacy summary and
    non-diagnostic limitation.
-   SRS-F-003: App shall support English and Vietnamese.
-   SRS-F-004: User language choice shall persist locally.
-   SRS-F-005: User shall be able to change language in Settings.
-   SRS-F-006: Changing language shall not change stored answer values
    or scoring.

### 4.2 Assessment session

-   SRS-F-010: App shall load question sets by assessment type and
    content version.
-   SRS-F-011: Every question shall have stable ID, dimension, item
    type, localized prompt, required flag and scoring metadata.
-   SRS-F-012: Self-report items shall accept one Likert response from 1
    to 5.
-   SRS-F-013: Situational items shall accept one option from the
    defined option set.
-   SRS-F-014: User shall navigate back and forward without losing
    answers.
-   SRS-F-015: Session state shall persist after each answer or
    navigation event.
-   SRS-F-016: User shall be able to resume an incomplete session.
-   SRS-F-017: User shall be able to abandon a session after
    confirmation.
-   SRS-F-018: App shall prevent completion while required questions are
    unanswered.
-   SRS-F-019: Question order shall be deterministic for a given
    assessment content version. Do not randomize in MVP.
-   SRS-F-020: A completed session shall become immutable. Retake
    creates a new session.

### 4.3 Scoring

-   SRS-F-030: Scoring shall be implemented in a pure domain service
    independent of UI.
-   SRS-F-031: Scoring shall use the exact formulas and item keys in
    `SCORING_SPEC.md`.
-   SRS-F-032: Reverse scoring shall be applied only to items explicitly
    flagged.
-   SRS-F-033: Situational items shall use explicit keyed option scores.
-   SRS-F-034: The engine shall calculate four dimension indices and an
    overall product reflection index.
-   SRS-F-035: Engine shall return scoring/content version with every
    result.
-   SRS-F-036: Engine shall reject unknown question IDs, invalid option
    values and incomplete required responses.
-   SRS-F-037: Unit tests shall cover minimum, maximum, reverse-scored,
    scenario-scored and mixed-item cases.

### 4.4 Results and content

-   SRS-F-040: Result screen shall show overall index and four dimension
    indices.
-   SRS-F-041: Result screen shall show a visible caveat that this is
    not a validated or diagnostic EQ measure.
-   SRS-F-042: Full result shall include dimension summaries,
    answer-based reflections and 7-day practice suggestions.
-   SRS-F-043: Result text shall be selected from authored content
    rules, not generated by an online AI service.
-   SRS-F-044: Result wording shall avoid diagnosis and deterministic
    personality labels.
-   SRS-F-045: User shall be able to revisit completed results from
    History.
-   SRS-F-046: Result sharing shall export a composed image through the
    native share sheet. Sharing is user initiated.
-   SRS-F-047: Shared image shall not include raw answers or sensitive
    item-level details.

### 4.5 Local storage

-   SRS-F-050: App shall store sessions, answers, results and settings
    locally.
-   SRS-F-051: Local records shall include schema version and
    content/scoring version.
-   SRS-F-052: App shall handle database migration without silent data
    loss.
-   SRS-F-053: User shall be able to delete all assessment history and
    answers.
-   SRS-F-054: Delete-data action shall require confirmation and remove
    associated sessions, answers and results.
-   SRS-F-055: No first-party server transmission of assessment data is
    permitted.

### 4.6 Premium and IAP

-   SRS-F-060: Product ID shall be `eqtest_premium_lifetime`.
-   SRS-F-061: Product type shall be non-consumable.
-   SRS-F-062: StoreKit product metadata and localized price shall be
    loaded dynamically.
-   SRS-F-063: Full Assessment shall be gated by verified Premium
    entitlement.
-   SRS-F-064: Successful purchase shall unlock Premium after
    transaction state is verified.
-   SRS-F-065: Cancelled, pending or failed purchase shall not unlock
    Premium.
-   SRS-F-066: Restore Purchases shall be available from paywall and
    Settings.
-   SRS-F-067: Entitlement shall refresh on app launch, purchase updates
    and restore.
-   SRS-F-068: App shall gracefully handle StoreKit/network
    unavailability and retain access to free features.
-   SRS-F-069: Premium users shall not receive app ads.
-   SRS-F-070: App shall provide a clear purchase disclosure and links
    to Terms and Privacy Policy.

### 4.7 Advertising

-   SRS-F-080: Ads may be shown only on approved non-assessment
    surfaces.
-   SRS-F-081: Ads shall not appear on question, completion, result or
    paywall screens.
-   SRS-F-082: Ads shall be disabled for Premium entitlement.
-   SRS-F-083: App shall implement applicable consent and
    tracking-permission behavior.
-   SRS-F-084: Assessment answers, scores and dimensions shall never be
    used for ad personalization or passed as ad request parameters.
-   SRS-F-085: If consent state is unknown or required consent has not
    been obtained, use the conservative compliant ad mode or do not
    request ads.

## 5. Non-functional requirements

### Performance

-   NFR-P-001: Cold launch should be responsive on supported iPhones;
    avoid synchronous heavy work on UI thread.
-   NFR-P-002: Question navigation should feel immediate.
-   NFR-P-003: Score calculation for 40 items should complete within 100
    ms on target devices.
-   NFR-P-004: Result chart rendering should not block interaction.

### Reliability

-   NFR-R-001: Save answer changes transactionally.
-   NFR-R-002: App interruption must not corrupt an in-progress
    assessment.
-   NFR-R-003: Database migrations must be tested from the previous
    released schema.
-   NFR-R-004: Purchase state must be recoverable via StoreKit restore.

### Security and privacy

-   NFR-S-001: Do not collect names, email, contacts, location or health
    records.
-   NFR-S-002: Do not transmit answers or results to third parties.
-   NFR-S-003: Do not log raw answer values or result details in
    production logs.
-   NFR-S-004: Use platform secure storage only for secrets/tokens if
    any are introduced; MVP should have none.
-   NFR-S-005: Privacy disclosures must accurately reflect ad and
    purchase SDK behavior.
-   NFR-S-006: Provide a local data deletion control.
-   NFR-S-007: Do not claim end-to-end encryption or encryption at rest
    unless verified.

### Accessibility

-   NFR-A-001: Support VoiceOver labels and logical focus order.
-   NFR-A-002: Do not use color as the sole indicator of score category.
-   NFR-A-003: Support Dynamic Type / text scaling without clipping.
-   NFR-A-004: Touch targets should meet Apple accessibility guidance.
-   NFR-A-005: Respect Reduce Motion where practical.
-   NFR-A-006: Charts must have accessible textual summaries.

### Localization

-   NFR-L-001: No user-facing text shall be hardcoded in widgets.
-   NFR-L-002: English and Vietnamese strings shall be complete.
-   NFR-L-003: Dates, numbers and currency shall use locale-aware
    formatting.
-   NFR-L-004: Question IDs and scoring metadata shall remain identical
    across locales.
-   NFR-L-005: Vietnamese translations shall be reviewed for natural
    tone and semantic equivalence.

## 6. Data model

### AssessmentDefinition

-   assessmentType: `quick` \| `full`
-   contentVersion: string
-   questionIds: ordered list

### Question

-   id: stable string
-   dimension: enum
-   itemType: `self_report` \| `situational`
-   prompt: localized string
-   responseScale: enum
-   reverseScored: boolean (self-report only)
-   optionScores: map (situational only)
-   required: boolean

### AssessmentSession

-   id: UUID
-   assessmentType
-   status: `in_progress` \| `completed` \| `abandoned`
-   startedAt, updatedAt, completedAt
-   contentVersion
-   scoringVersion
-   localeAtStart

### Answer

-   sessionId
-   questionId
-   selectedValue
-   answeredAt

### AssessmentResult

-   sessionId
-   overallIndex
-   dimensionIndices
-   interpretationBand
-   contentVersion
-   scoringVersion
-   createdAt

### EntitlementCache

-   productId
-   entitlementState
-   lastVerifiedAt
-   transactionReference (only if appropriate; avoid storing unnecessary
    transaction data)

## 7. Error and edge-case handling

-   Missing bundled question asset: show controlled error; do not create
    a partial score.
-   Invalid question metadata: fail validation in development and
    automated tests.
-   App killed during test: resume session.
-   Duplicate purchase callback: process idempotently.
-   StoreKit pending: show pending state; do not unlock.
-   Restore with no purchases: show neutral message.
-   Ad load failure: hide ad container; do not block content.
-   Language changed during active test: keep current session language
    or apply only after session ends; do not mix languages in one
    session.
-   Delete local data: require confirmation; preserve purchase
    entitlement because purchase belongs to Apple account, not local
    assessment data.

## 8. Test requirements

-   Unit tests: scoring, reverse scoring, scenario keys, thresholds,
    result rules, entitlement gate.
-   Widget tests: question selection, navigation, progress, paywall
    states, result views, accessibility labels.
-   Integration tests: complete Quick Test, premium purchase sandbox,
    restore, offline test, relaunch/resume, delete data.
-   Localization tests: missing keys, text overflow, Vietnamese
    diacritics.
-   Regression tests: content version and scoring version changes.
-   Manual tests: supported iOS versions/devices and VoiceOver.

## 9. Definition of done

A requirement is done only when implementation, tests, error states,
localization, accessibility and documentation are complete. A screen
that merely renders is not accepted as a completed feature.
